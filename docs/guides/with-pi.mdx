Install the HyperFrames skills, then ask Pi for a video. Pi writes an HTML
project in your folder, opens a live preview, and renders the MP4 on your
computer.

```bash
npx hyperframes skills update
```

This installs the core skills into your user's shared skills folder,
`~/.agents/skills`, which Pi reads in every project. Pi needs no plugin to use
them.

## Before you start

- [Pi](https://github.com/earendil-works/pi), signed in to the provider whose
  models you want to use. Its usage bills to that provider.
- Node.js 22 or newer, and npm.
- FFmpeg, for rendering MP4 files. Run `npx hyperframes doctor` to check.

## Install

Run the command above once. Run it again later to update the skills.

To keep the skills with one project instead, run this in the project folder and
choose **Core Skills** and **Pi** in the picker:

```bash
npx skills add heygen-com/hyperframes
```

That writes the skills to the project's `.agents/skills` folder. Pi asks for
project trust when it finds that folder; grant it so the skills load, and read
the skill files first if the project is unfamiliar.

Start a new Pi session after either install. See
[Install and update agent skills](/guides/skills) for checking and updating.

## Ask for your first video

Open Pi in an empty folder and paste:

```text
/skill:hyperframes make a 10-second product intro for https://example.com.
```

Pi loads a skill with `/skill:<name>`, so the command is `/skill:hyperframes`.
Naming the skill in plain words works too, because Pi selects it from the skill's
description. Replace the URL with the page you want the video to show.

## What happens

1. Pi reads the HyperFrames guide for your kind of video, such as a product
   launch or an explainer, and builds the project in your folder. For a longer
   film that tells a story, it first offers three storylines to pick from.
2. It checks the project and opens a local preview.

Pi runs commands without asking each time, so start it in a folder you are
willing to let it change. The skills install packages, start a preview server,
and run the renderer. Watch the first version and say what to change, in the
same session.

## Preview and render

To reopen the preview later, run this inside the project folder:

```bash
npx hyperframes preview
```

The preview opens in the browser editor, where you can also edit the video by
hand. To make the MP4 yourself:

```bash
npx hyperframes render --output final.mp4
```

You can also ask Pi to render it.

## If something goes wrong

- **Pi does not offer `/skill:hyperframes`.** Start a new session. Confirm that
  `~/.agents/skills/hyperframes` (user install) or `.agents/skills/hyperframes`
  (project install) exists, then run `npx hyperframes skills check`.
- **Pi ignores a project install.** Grant project trust when Pi asks, or start it
  with `pi --approve` in that folder. Declining trust makes Pi skip the project's
  `.agents/skills`.
- **The render fails.** Run `npx hyperframes doctor` and fix what it reports.
- **Anything else.** See [Troubleshooting](/help).
