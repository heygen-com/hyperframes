The contract, per boundary

Core paint-and-idle input

A fixed cutoff currently treats every steady slow frame as busy. Two quiet gaps settle early; 1.5 seconds of continuing frames ends the paint wait.

export function paintAndIdleReadinessInput(
  doc: Document,
  signal: AbortSignal,
): Promise<void> | null {
  const win = doc.defaultView;
  if (!win) return null;
  return (async () => {
    const firstTs = await nextAnimationFrame(win, signal);
    if (signal.aborted) return;
    let lastTs = await nextAnimationFrame(win, signal);
    let quietStreak = 0;
    while (!signal.aborted && quietStreak < IDLE_FRAMES_REQUIRED) {
      if (lastTs - firstTs >= MAX_PAINT_WAIT_MS) return;
      const ts = await nextAnimationFrame(win, signal);
      if (signal.aborted) return;
      quietStreak = ts - lastTs < IDLE_FRAME_GAP_MS ? quietStreak + 1 : 0;
      lastTs = ts;
    }
  })();
}

How it says no

SignalMeaning and action
nullNo document window, no paint input is pending.
AbortSignalShared timeout or completion cancels remaining frame requests.
timedOut: trueShared 8-second wait elapsed. Player warns and continues; this is not proof of idle.
Generation mismatchOld load cannot mark the current picture ready.

Decisions only you can make

1. Which stabilization rule counts as idle?

Your supplied decision is document-relative gaps. The exact tolerance and sample history remain unknown until measured traces show ordinary variation and busy recovery.

OptionConsequence
Recent gap stabilitySteady slow documents settle promptly. A stable sustained workload can also look idle.
Relative return to observed baselineDetects recovery from busy gaps, but a document that starts busy may supply a misleading baseline.

Recommendation: measure both against steady slow, burst/recovery and continuing-busy traces before choosing parameters. Preserve two-gap confirmation and existing timeout/abort semantics unless the evidence requires a separate decision.
