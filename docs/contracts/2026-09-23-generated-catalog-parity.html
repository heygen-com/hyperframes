Generated catalog parity

Committed registry and catalog files must match the complete generation pipeline.

Audited: 5 boundaries · Trusting: 0 · Not exercised: full generation and CI · Decisions: pipeline scope for review

The registry index feeds page discovery. Pages feed navigation, then gallery sync rewrites that navigation. Compare the final pipeline output, not an intermediate file.

Where the value travels

Item manifests → registry.json → catalog pages + catalog-index.json + docs.json → gallery data + final docs.json → committed-tree comparison

All arrows are source-audited. Runtime equality is not yet exercised.

The contract, per boundary

1. Registry index

Existing item directories determine index membership. The full script also scaffolds example manifests, so the index write needs its own callable entry.

items.push({ name, type });
writeFileSync(registryManifestPath, JSON.stringify(manifest, null, 2) + "\n", "utf-8");
Producer: scripts/generate-registry-items.ts:161-205. Consumer: scripts/generate-catalog-pages.ts:115-151.

Exists: yes. Reachable: full generator only. Written/read: both. Preserve catalogArtifact, which has a separate owner.

The generator reads authored sections before replacing the generated page directories.

Exists: yes. Reachable: direct script. Written/read: pages, flat catalog index and docs navigation. Existing prose is an input, not disposable output.

3. Gallery and final navigation

Gallery sync consumes navigation, emits gallery data, then rebuilds navigation from that data.

buildNav(docs);
tab.groups = [{ group: "Catalog", pages: ["catalog/index", ...groups] }];
Producer/consumer: scripts/sync-docs-catalog.mjs:148-154; scripts/build-docs-gallery-nav.mjs:14-42.

Exists: yes. Reachable: sync script calls buildNav. Written/read: gallery data and final docs.json. The single-child navigation fix must precede regeneration.

4. Existing drift check

The check compares generated payload bytes with Git's committed tree, so ignored local files cannot hide missing commits.

export function treeDifferences(generatedRoot: string, committedRoot: string): string[]
Producer: scripts/catalog-drift.ts:22-39; Git extraction: 51-63; consumer: 72-78.

Exists: yes. Reachable: check:catalog-drift. Written/read: payload tree only today. Proposed extension uses the same helper for registry index, pages, catalog index, gallery data and final navigation.

5. CI and the set guard

The existing guard currently rejects restoring an index entry when its source file already existed on the base branch.

node scripts/check-registry-set-delta.mjs origin/main && tsx scripts/catalog-drift.ts
Producer: package.json:37; consumer: .github/workflows/ci.yml:230. Membership rule: scripts/check-registry-set-delta.mjs:19-26 and 38-45.

Exists: yes. Reachable: Catalog payloads job. Written/read: base/head item sets. Permit restoration backed by tracked source; preserve rejection of invented entries and unbacked deletions. Add the registry generator to the job's path filter.

Scope for review

The requested invariant is already decided. The implementation shape includes gallery sync because it is the current final writer of docs.json. Checking the page generator alone would reject the published navigation shape. No new grouping system or page template is proposed.

Before implementation: review this boundary map and obtain the navigation fix's exact ref. The repair must follow that fix.

What would prove this page wrong

  • Run the full pipeline twice: the second output must be byte-identical.
  • Change one generated file in a disposable Git commit: the check must name that path and fail. Restore it and require success.
  • Restore an index entry backed by tracked source: the set guard must accept it. Invent an entry or remove one whose source remains: it must reject it.
