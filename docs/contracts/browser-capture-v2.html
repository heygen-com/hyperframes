One element.
One paste.
One undo.

Build a Chrome extension that lets a creator point at one visible web element, lock an honest local capture, copy it, and paste it into the current HyperFrames Studio composition as one selected, visible, undoable child composition.

What this turned out to be

This is not an HTML copy button. It is an eight-boundary import transaction where hostile page state becomes inert project files, then earns the right to appear selected only after preview acknowledgement.

Boundary map

The clipboard is a courier, not a security seal.

1. Hostile page

DOM, CSS, pixels, forms, remote resources, page events, and page scripts.

2. Isolated picker

One epoch, one target, bounded capture, protected-field redaction.

3. V2 builder

Shared schema, canonical bytes, resources, diagnostics, claims, digest.

4. OS clipboard

Mutable, forgeable, persistent or synchronized by the operating system.

5. Native paste

Fresh bytes from the user-triggered ClipboardEvent. Exact prefix claims the event.

6. Import planner

Parse, quotas, inert DOM, sanitizer, CSS policy, resources, identity graph.

7. Local server

The request remains hostile until capability, Origin, Host, body, paths, and plan pass again.

8. Project + preview

Pointer-last commit, history receipt, refresh, preview acknowledgement, selection.

Proposed grammar, not runtime fact

reserved-prefix LF canonical-json EOF

canonical-json owns exactly:
  version       exact supported v2.0
  audience      hyperframes-studio
  artifact      editable-dom | finite-local-media | still
  resources     bounded opaque ids + declared bytes + sha256
  diagnostics   closed producer codes, sorted
  claims        source-frame + time + reflow
  integrity     algorithm + digest over the declared scope

No raw URL. No page script. No operationId.
No source data-hf-id. No compressed alternate form.

One owner, one reader

  • Prefix + versionShared v2 contract owns. Native paste broker reads once to claim or leave the event.
  • Artifact unionPure capture classifier writes. Shared schema and Studio planner read exhaustively.
  • ResourcesCapture resource builder writes. Studio and server validators read before materialization.
  • DiagnosticsClosed shared registry owns codes. Extension and Studio each own only localized copy.
  • ClaimsClassifier writes source-frame, time, and reflow separately. Capsule and Studio summary read.
  • IntegrityCanonical serializer writes. Shared parser verifies before hostile DOM parsing.
  • operationIdStudio mints after paste. It never comes from the clipboard or hostile page.

The server owns the durable outcome.

Server capability lifecycle

MintVite or CLI server creates a high-entropy capability per process and authorized Studio session.
DeliverNon-cacheable Studio bootstrap binds it to process, session, and project scope.
PresentStudio sends it in a non-simple request header. Origin and Host must match before body parsing.
AuthorizeSubmit, status, receipt acknowledgement, Undo, and Redo share the same deny-by-default boundary.
ExpireBounded lifetime, project/session mismatch, or server restart revokes it. Replay becomes zero-write.
05

Threat model and refusals

Every layer gets its own way to say no.

Hostile page code

Copy handlers, event traps, constructors, scripts, framework bundles, and shaders may try to cross the boundary.

Control: isolated world, extension-owned clipboard context, inert parsing, closed sanitizer, zero surviving page code.

Forged clipboard

Any application can forge a marker, MIME, digest, or envelope.

Control: markers route, never authorize. Studio treats every envelope as hostile and validates from bytes.

Stale Studio memory

An old internal copy can be duplicated when the OS clipboard contains unrelated text.

Control: native event owns freshness. Unrecognized text never falls back to stale memory.

Remote resource escape

HTML, SVG, or CSS may hide network and executable URLs through encoding or indirection.

Control: one canonicalizer, local resource ids only, parsed CSS, final-tree network invariant.

Identity clobbering

Duplicate ids, dangling references, source data-hf-id, or DOM clobbering can bind to the wrong object.

Control: graph rewrite after sanitization, ambiguous referenced duplicates reject, canonical HF allocator runs last.

Partial commit

A process may die after resources, child, parent, or response while the user sees no answer.

Control: durable journal, referents first, parent pointer last, operationId reconciliation, CAS rollback.

Worker restart

MV3 global state can disappear between activation, capture, and copy.

Control: content document owns immutable locked artifact. Worker messages are idempotent and carry identity plus epoch.

Same-origin preview

Current preview execution is not a containment boundary if hostile code survives.

Control: imported page code never survives. Active-code capture requires a separate product and origin.

Unauthorized localhost write

A malicious web page can target local mutation routes unless the server authenticates Studio.

Control: server-issued capability, exact Origin and Host, non-simple header, deny CORS, authorize before body parse.

Coverage, honestly

Source-audited is not end-to-end exercised.

Audited

Current and recovered producers and consumers were opened at exact refs. Studio memory-only clipboard, dormant v1 serializer, present-only history, versioned file writes, and composition insertion were traced to accepting lines.

Trusting

The proposed v2 grammar, policy taxonomy, capability lifecycle, lifecycle receipt, and package profile come from the approved plan. They do not exist at the current ref and must not be described as shipped behavior.

Not exercised

No target creator tested this prototype. The real Chrome permission prompt was not shown to target creators. No OS clipboard to Studio import ran. No hostile corpus, crash matrix, preview acknowledgement, Undo, pixel threshold, or deterministic double build ran.

2

Hybrid representation

This decides whether fidelity or editability wins when a selection contains opaque descendants.

Hybrid + escape hatchKeep safe DOM editable, replace honest opaque islands in place, and fall back for the whole selection when layout would lie.
Whole-selection stillSimpler and safer, but destroys editability whenever one opaque descendant appears.
DOM onlyMaximum editability claim, but opaque visuals disappear or become misleading. Not recommended.
3

V2 motion floor

Typed motion translation multiplies scope and trust surfaces before the direct capture loop is proven.

Finite local mediaStaticize DOM motion at lock. Allow bounded canvas, video, and WebGL media with explicit time claims. Defer typed motion.
Static onlyMuch smaller v2, but weak for visually distinctive web fragments and likely misses the product’s emotional promise.
Typed motion nowMore editable, but materially expands capture semantics, determinism, tests, and failure modes before activation is proven.

08

What would falsify this page

A contract should be easy to prove wrong.

Current source

A production caller of deserializeClipboardPayload or a native outer-document paste broker at ref 859ac622c would falsify the claim that external ingress is absent.

User model

Target creators who naturally expect Copy to mean “already imported” would falsify the two-product handoff copy and block U2 until the flow changes.

Permission

A real staged package whose aggregate install prompt differs from the documented warning would reopen D1 and the manifest profile.

Representation

A fixture where hybrid island replacement changes layout while whole-selection fallback preserves it would prove the classifier needs the escape hatch.

Security

Any captured fixture that executes source code or makes an external request during import, preview, reload, or render falsifies the trust model.

Durability

Any crash cut point that leaves a live parent pointing at a missing child or makes the outcome unqueryable falsifies pointer-last recovery.
