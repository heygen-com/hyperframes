# HyperFrames v0.8.184

Released on 2026-10-21.

`hyperframes cloud render` now takes projects whose media is far larger than the project upload limit. Multi-worker mp4 renders start encoding while they capture, Lambda chunks run more capture browsers at once, and a heavy project's preview builds faster. Transparent webm keeps its transparency in Studio previews, and a color grade applies to an image that appears after its scene starts hidden.

## Features

- **CLI:** `cloud render` uploads media of 5 MB or more as hosted assets before zipping the project, so projects with media far larger than the upload limit render with no manual step. Uploads are cached, so a re-render sends only new or changed media ([b306438e8](https://github.com/heygen-com/hyperframes/commit/b306438e8b5e2199db1ed07e6eb4332d53131048), [#5931](https://github.com/heygen-com/hyperframes/pull/5931)).

## Fixes

- **Studio Server:** A transparent VP8 or VP9 webm, such as `remove-background` output, keeps its transparency in the preview copy that `check`, Studio and publish make ([d67e81c7f](https://github.com/heygen-com/hyperframes/commit/d67e81c7f1a804bec337463bfa7b6f46f278b25d), [#6025](https://github.com/heygen-com/hyperframes/pull/6025)).
- **Core:** A color-graded image renders graded in `snapshot` and `render` when it is hidden as its scene starts and revealed later ([087451837](https://github.com/heygen-com/hyperframes/commit/087451837b16cb9ae74f7932a4a18af86e3a012d), [#6012](https://github.com/heygen-com/hyperframes/pull/6012)).
- **CLI:** A `preview` refused inside a host app no longer stops other Chrome processes left behind by earlier runs ([5641a9179](https://github.com/heygen-com/hyperframes/commit/5641a9179acd821dfa3a6a69725beb31de6b7a5b), [#6022](https://github.com/heygen-com/hyperframes/pull/6022)).

## Performance

- **Producer:** A multi-worker mp4 render starts encoding while its frames are still being captured, instead of after, with byte-identical output ([eec3c51d7](https://github.com/heygen-com/hyperframes/commit/eec3c51d7509365c388b4a962a7156cbb52ae62a), [#5952](https://github.com/heygen-com/hyperframes/pull/5952)).
- **AWS Lambda:** Each chunk renders with as many capture browsers as the function can host, five instead of three on a 10 GB function, so heavy 4K chunks finish sooner ([cde21630e](https://github.com/heygen-com/hyperframes/commit/cde21630e46dc9540b42876d0de3738d4b6bf5c2), [#6026](https://github.com/heygen-com/hyperframes/pull/6026)).
- **Core:** A heavy project's first preview page builds sooner, without rescanning its styles once per composition variable ([0d51eb0de](https://github.com/heygen-com/hyperframes/commit/0d51eb0de46b2179acf982d5cc7d0a17e9316ee8), [#5893](https://github.com/heygen-com/hyperframes/pull/5893)).
- **Core:** A page build reads fonts, inlined assets and scenes mounted many times only once, and an offline build with a warm font cache makes no network request ([884d8690a](https://github.com/heygen-com/hyperframes/commit/884d8690af6906ddffe971e15bd5a1b24921e13b), [#5954](https://github.com/heygen-com/hyperframes/pull/5954)).
