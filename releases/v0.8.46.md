# HyperFrames v0.8.46

Released on 2026-09-17.

Engine motion blur picks its own sample count per frame now, instead of one fixed count for a whole render.

## Features

- **Engine:** The sub-frame motion blur added in v0.8.45 used a fixed sample count for every frame of a render (16 by default). That undersamples fast or hard-edged motion and oversamples content that barely moves. The engine now measures how much a frame actually moved before choosing how many samples it gets, between 16 and 64, so quality goes up where it was undersampled and render time drops where it was not needed. A frame whose only change is a fade or a colour shift skips the extra measurement step entirely, since that kind of change does not need many samples to look right. Nothing changes if `samplesPerFrame` is set explicitly ([2ab7b8686](https://github.com/heygen-com/hyperframes/commit/2ab7b8686870cb435674e20d48b4100db2fa2052), [#4031](https://github.com/heygen-com/hyperframes/pull/4031)).
