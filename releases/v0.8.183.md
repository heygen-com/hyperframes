# HyperFrames v0.8.183

Released on 2026-10-21.

v0.8.182 was tagged but never reached npm (its publish stopped at the package size check), so everything listed for it ships in this release.

Website capture now handles pages that reload after a cookie banner, CLI commands start faster, a repeat `check` starts with the CLI and Chrome already up, and `snapshot` and `check` wait for late images as `render` does. Renders inside a macOS sandbox no longer fail, a sharp sound at a film's start no longer grows louder with each audio pass, and `lambda sites create` takes source files over 5 GB. Cloud renders mix their audio beside the chunks and fail loudly when an audio read is cut off, a 4K camera shown small reaches Chrome near the size it is drawn, a finished `capture` exits even when a site's DNS never answers, and an unreadable frame fails a render instead of shortening it.

## Features

- **AWS Lambda:** A cloud render mixes its audio on its own Lambda while the chunks render, instead of before them, so a long film finishes sooner ([dee8380d2](https://github.com/heygen-com/hyperframes/commit/dee8380d2295070353aac1f98deb28c030d86572), [#5997](https://github.com/heygen-com/hyperframes/pull/5997)).
- **Producer:** A cloud plan can leave its audio out and build that track on its own, which the Lambda change above uses ([8b410f1cb](https://github.com/heygen-com/hyperframes/commit/8b410f1cb1b0d8e0d433da7fdc7942565c29af2c), [#5988](https://github.com/heygen-com/hyperframes/pull/5988)).
- **Registry:** New `echo-smear` component: a streak of copies that trails an element as a GSAP timeline moves it faster ([23e7a384b](https://github.com/heygen-com/hyperframes/commit/23e7a384b623e1c7125f1021e93363fd34f42043), [#5980](https://github.com/heygen-com/hyperframes/pull/5980)).
